# Сетевые ссылки TabPrefix 2.0.2

## Домашний сервер без проброса порта

Компьютер с сервером уже должен быть подключён к локальной сети средствами ОС. Для браузера на этом компьютере или другом устройстве в той же доступной LAN проброс порта на роутере не нужен.

Добавьте или измените следующие поля в существующем `config.yml`, сохранив остальные настройки. Не создавайте второй раздел `web` или `resource-pack`:

```yaml
web:
  enabled: true
  bind-address: "0.0.0.0"
  port: 8765
  auto-port: true
  public-host: ""
  public-base-url: ""

resource-pack:
  public-base-url: ""
```

Полностью перезапустите сервер. Откройте `/lptab linkwifi` в игре: список содержит названия интерфейсов и IP компьютера с сервером, фактический HTTP-порт, текущий адрес и кнопку автоматического выбора. Строки содержат готовую команду и остаются читаемыми, если click events отключены. Ссылка health проверяет доступность HTTP и не содержит токена редактора.

Нажатие строки выбирает этот адрес для игрока и открывает новую сессию его текущей группы LuckPerms. Уже выданная этому игроку сессия отзывается. Для редактирования другой группы после выбора используйте `/lptab webeditor <group>` с правом `tabprefix.prefix.manage`.

| Команда | Результат |
|---|---|
| `/lptab linkwifi` | Состояние HTTP и интерактивный список адресов сервера |
| `/lptab linkwifi 192.168.1.50` | Выбрать адрес из текущего списка и открыть личный редактор |
| `/lptab linkwifi auto` | Сбросить ручной выбор и открыть редактор с автоматическим адресом |
| `/lptab webeditor` | Открыть редактор с текущим ручным или автоматическим выбором |
| `/tabprefix:lptab doctor` | Показать установленную версию, ready и конкретное состояние HTTP |

Для `linkwifi` нужны `tabprefix.use` и `tabprefix.webeditor`; они входят в `tabprefix.user.*` и `tabprefix.admin.*`. В консоли список и состояние доступны с соответствующими правами, но личные сессии создаются в игре. Настройки сети требуют полного перезапуска, не `/reload`.

## Как выбираются IP и порт

Плагин перечисляет активные сетевые интерфейсы через Java NetworkInterface. Это может быть Ethernet, Wi-Fi, VPN или loopback. Он не сканирует окружающие SSID и не определяет пароль сети. Имя интерфейса не выдаётся за имя Wi-Fi. Переключение и подключение к Wi-Fi остаётся в настройках ОС игрока/хоста.

Приоритет для автоматической ссылки: явный public URL/host, затем подходящий адрес в подсети игрового подключения, затем предпочтительный локальный адрес сервера. С учётом subnet comparison доступны IPv4 и IPv6; виртуальные интерфейсы и loopback имеют меньший общий приоритет. Для игрового подключения с localhost используется loopback. Если Minecraft подключён через proxy, плагин может видеть IP proxy — тогда вручную выберите доступный вашему браузеру адрес.

Ручной выбор ограничен найденными адресами сервера, действует до двух часов, не меняет глобальную конфигурацию и не влияет на других игроков. Адреса обновляются при новых обращениях, с кэшем до трёх секунд. Если выбранный IP исчез, новые ссылки снова используют автоматический выбор. После смены адреса откройте новую сессию: уже открытая ссылка сохраняет прежний адрес. При binding на конкретный исчезнувший IP потребуется исправить binding и перезапустить сервер.

В автоматическом режиме сначала используется `web.port`. Если он занят, проверяются до двадцати портов начиная с предпочтительного, затем ОС назначает свободный порт. `web.port: 0` сразу выбирает порт средствами ОС. В `/linkwifi`, `/status`, `/doctor`, редакторе и новых ресурс-пак ссылках используется фактический порт. HTTP binding выполняется перед загрузкой/сборкой активного ресурс-пака.

При явном `web.public-host`, `web.public-base-url` или `resource-pack.public-base-url` автоматически менять порт нельзя: внешний proxy, firewall/NAT или отдельный pack host может ожидать фиксированное значение. Поэтому подбор порта выключен независимо от `auto-port`. Для такого режима задайте конкретный `web.port` от 1 до 65535. `web.auto-port: false` также сохраняет фиксированный порт. Уже настроенные HTTPS/proxy адреса имеют прежнее поведение.

## Если редактор недоступен

| Наблюдение | Проверка |
|---|---|
| `starting` | Дождаться startup; если не меняется, проверить лог и `doctor` |
| `disabled` | Включить `web.enabled` и перезапустить сервер |
| `bind-failed` | Читать причину ошибки; проверить существующий IP binding и занятый порт; убрать явные адреса только если нужен автоматический LAN-режим |
| `start-failed` | Проверить конкретную ошибку в startup log |
| `listening`, но health не открывается | Проверить выбранный адрес, общую LAN/маршрут, брандмауэр хоста и client isolation/guest Wi-Fi |
| Работает только на серверном компьютере | Проверить `web.bind-address`, не выбран ли `127.0.0.1`, доступ браузера к LAN и разрешение входящего HTTP |
| `doctor` показывает другую версию | Остановить сервер, заменить единственный JAR TabPrefix и запустить заново |

`TabPrefix Editor is not ready!` само по себе не доказывает проблему Wi-Fi. В 2.0.2 диагностика показывает, запущен ли HTTP и почему он не запустился. Если HTTP принимает подключения, проблема открытия URL проверяется отдельно с устройства игрока. При необходимости разрешите в брандмауэре именно показанный порт: плагин не меняет firewall или настройки роутера.

Автоматический подбор локального адреса не создаёт туннель между разными сетями и не определяет публичный адрес за NAT. Для удалённых игроков используйте уже настроенный внешний URL/reverse proxy или отдельный туннельный сервис. Такой сервис в плагин не встроен. Название и пароль другой Wi-Fi сети не делают её доступной серверу.

## Обновление с 2.0.1

Остановите сервер, замените JAR, сохраните существующие `plugins/TabPrefix/config.yml`, файлы сообщений, базу и media, затем запустите сервер. Новые default keys доступны через bundled defaults; перезаписывать ваши YAML не требуется. Для автоподбора уберите прежние явные адреса только если они больше не нужны. Проверьте `version=2.0.2` и `state=listening` в `/tabprefix:lptab doctor`, затем откройте health и редактор с нужного устройства.

Проверено автоматически: 52 сетевые проверки, прежние интеграционные проверки и реальный браузер. Здесь не выполнялись запуск Minecraft-сервера, подключение игрового клиента и проверка конкретного домашнего роутера/брандмауэра.
